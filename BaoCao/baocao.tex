\chapter*{TÓM TẮT BÁO CÁO}
\addcontentsline{toc}{chapter}{TÓM TẮT BÁO CÁO}

Ùn tắc giao thông là một trong những vấn đề cấp bách nhất của Thành phố Hồ Chí Minh. Đề tài \textit{``Xây dựng giải pháp gom cụm tình trạng giao thông ở TP.HCM''} hướng tới việc nhận diện tự động các trạng thái giao thông điển hình của thành phố bằng kỹ thuật gom cụm dữ liệu, đồng thời đưa kết quả phân tích tới tay người tham gia giao thông thông qua một hệ thống ứng dụng hoàn chỉnh. Hệ thống gồm bốn thành phần:
\begin{enumerate}[label=(\roman*),leftmargin=2.2cm,itemsep=2pt]
    \item pipeline thu thập và xử lý dữ liệu giao thông đa nguồn (TomTom Traffic API, OpenStreetMap, Mapbox, Open-Meteo);
    \item pipeline học máy so sánh năm thuật toán gom cụm (K-Means, MiniBatchKMeans, DBSCAN, GMM, Agglomerative Clustering) bằng bộ chỉ số Silhouette, Davies--Bouldin, Calinski--Harabasz, ARI, NMI;
    \item ứng dụng di động \textbf{TraffiGo} trên nền Android cho người dùng đi đường;
    \item \textbf{server Machine Learning} (FastAPI) cung cấp API dự đoán tốc độ lưu thông, mức độ kẹt xe, rủi ro sự cố và gợi ý tuyến đường theo từng đoạn đường.
\end{enumerate}

Kết quả thực nghiệm cho thấy mô hình K-Means với $k=6$ trên nhánh Feature Selection đạt chất lượng gom cụm tốt nhất (Silhouette $0{,}4183$; Davies--Bouldin $0{,}8063$; Calinski--Harabasz $147574{,}6$) và cho phép diễn giải sáu trạng thái giao thông có ý nghĩa thực tiễn, từ ``tắc tuyệt đối/bất thường'' đến ``thông thoáng hoàn toàn''. Mô hình này được xuất ở dạng JSON và nhúng trực tiếp vào ứng dụng di động, giúp tô màu sáu mức trạng thái giao thông trên bản đồ trong thời gian thực mà không phụ thuộc máy chủ. Song song, mô hình Random Forest dự đoán tốc độ lưu thông được huấn luyện trên khoảng $149.000$ mẫu dữ liệu thu thập trong giai đoạn 09/03--15/04/2026, đạt MAE $2{,}19$ km/h (so với baseline $8{,}25$ km/h) và hệ số xác định $R^2 = 0{,}919$; mô hình được triển khai qua bộ REST API \texttt{/api/ml/*} và tích hợp hai chiều với ứng dụng: dự báo chi tiết theo đoạn đường và gợi ý tuyến đường tối ưu. Server chính thức hiện chạy trên Render Cloud tại \url{https://traffigo-server.onrender.com}; ứng dụng Android kết nối tới dịch vụ này và hiển thị chip xanh ``Server ML: đang hoạt động'' khi kiểm tra \texttt{/health} thành công. Ứng dụng đã vượt qua toàn bộ ca kiểm thử đơn vị và ca kiểm thử chức năng trên thiết bị giả lập.

\textbf{Từ khóa:} gom cụm dữ liệu, học máy không giám sát, K-Means, dự đoán giao thông, ứng dụng Android, FastAPI.

\chapter*{ABSTRACT}
\addcontentsline{toc}{chapter}{ABSTRACT}

Traffic congestion is one of the most pressing problems in Ho Chi Minh City. This project, \textit{``Building a traffic condition clustering solution for Ho Chi Minh City''}, aims to automatically identify the typical traffic states of the city using data clustering techniques, and to deliver the analysis results to road users through a complete application system. The system comprises four components:
\begin{enumerate}[label=(\roman*),leftmargin=2.2cm,itemsep=2pt]
    \item a multi-source traffic data collection and processing pipeline (TomTom Traffic API, OpenStreetMap, Mapbox, Open-Meteo);
    \item a machine learning pipeline that compares five clustering algorithms (K-Means, MiniBatchKMeans, DBSCAN, GMM, Agglomerative Clustering) using Silhouette, Davies--Bouldin, Calinski--Harabasz, ARI and NMI metrics;
    \item \textbf{TraffiGo}, an Android application for road users;
    \item a \textbf{Machine Learning server} (FastAPI) exposing APIs that predict traffic speed, congestion level and incident risk per road segment.
\end{enumerate}

Experiments show that K-Means with $k=6$ on the Feature Selection branch achieves the best clustering quality (Silhouette $0.4183$; Davies--Bouldin $0.8063$; Calinski--Harabasz $147574.6$) and yields six practically interpretable traffic states, from ``extreme congestion/anomaly'' to ``free flow''. This model is exported as JSON and embedded directly in the mobile application, coloring six real-time traffic states on the map without depending on a server. In parallel, a Random Forest speed-prediction model trained on approximately $149{,}000$ samples collected between 2026-03-09 and 2026-04-15 achieves MAE $2.19$ km/h (versus an $8.25$ km/h baseline) with $R^2 = 0.919$; the model is deployed through REST APIs (\texttt{/api/ml/*}) and integrated with the application for per-segment forecasting and route recommendation. The production server currently runs on Render Cloud at \url{https://traffigo-server.onrender.com}; the Android application connects to this service and shows a green ``Server ML: online'' status chip when the \texttt{/health} check succeeds. The application passed all unit tests and functional test cases on an Android emulator.

\textbf{Keywords:} data clustering, unsupervised learning, K-Means, traffic prediction, Android application, FastAPI.

\chapter{HƯỚNG DẪN CHẠY SERVER ML}
Server ML được đặt tại thư mục \texttt{E:\textbackslash Android\textbackslash TraffiGo\textbackslash server}, gồm ba thành phần: \texttt{train\_model.py} (huấn luyện và xuất mô hình), \texttt{app.py} (REST API) và thư mục \texttt{models/} (chứa các tệp mô hình). Các bước cài đặt và khởi chạy:
\begin{verbatim}
pip install -r requirements.txt
python train_model.py          # huấn luyện lại mô hình (chạy 1 lần)
uvicorn app:app --host 0.0.0.0 --port 8000
\end{verbatim}
Sau khi khởi chạy, giao diện tài liệu API (Swagger UI) tự sinh tại \url{http://localhost:8000/docs}. Ứng dụng Android mặc định gọi \url{http://10.0.2.2:8000} (địa chỉ loopback của máy phát triển nhìn từ trình giả lập chuẩn), sau đó tự thử \url{http://127.0.0.1:8000} (phù hợp khi dùng \texttt{adb reverse tcp:8000 tcp:8000} hoặc trình giả lập MuMu/LDPlayer); với thiết bị thật, người dùng đặt địa chỉ IP LAN của máy chủ trong SharedPreferences theo khóa \texttt{ml\_server\_url} (nhóm prefs \texttt{TraffiGoPrefs}). Khi máy chủ không khả dụng, mọi lời gọi ML tự fallback về logic tính toán trên thiết bị.

\section*{Máy chủ triển khai chính thức}
Môi trường production của TraffiGo ML Server được triển khai trên Render Cloud tại \url{https://traffigo-server.onrender.com}. Đây là host mặc định ứng dụng Android ưu tiên kết nối; ứng dụng kiểm tra \url{https://traffigo-server.onrender.com/health} để xác định trạng thái server và hiển thị chip xanh ``Server ML: đang hoạt động'' khi kết nối thành công. URL localhost và các địa chỉ emulator ở trên chỉ phục vụ phát triển cục bộ; server production dùng HTTPS và biến môi trường \texttt{PORT} do nền tảng cung cấp.

\chapter{ĐẶC TRƯNG CÁC MÔ HÌNH}
\textbf{Nhóm gom cụm --- 9 thuộc tính của nhánh Feature Selection:}
\begin{itemize}[nosep]
    \item speedLimitRatio (tỉ lệ tốc độ hiện tại trên giới hạn tốc độ), crossTime (thời gian vượt đoạn), trafficVolume (lưu lượng ước lượng);
    \item congestionIndex (chỉ số ùn tắc), occupancy (độ chiếm dụng mặt đường), relativeCongestionIndex (chỉ số ùn tắc tương đối);
    \item freeFlowSpeed (tốc độ dòng tự do), lengthKm (chiều dài đoạn đường), curvatureIndex (chỉ số độ cong).
\end{itemize}
\textbf{Nhóm dự đoán tốc độ --- Random Forest:}
\begin{itemize}[nosep]
    \item Thuộc tính số: freeFlowSpeed, speedLimit, hourOfDay, dayOfWeek, laneCount (số làn), intersectionCount (số giao lộ), routeSlopePercent (độ dốc), curvatureIndex, lengthKm;
    \item Thuộc tính thời tiết: precipitation (lượng mưa), windspeed (tốc độ gió), temperature (nhiệt độ cao nhất trong ngày);
    \item Thuộc tính phân loại (one-hot): roadType (loại đường), surface (bề mặt), dayType (loại ngày);
    \item Biến đích: currentSpeed.
\end{itemize}
Cả currentSpeed, congestionIndex và jamFactor đều \textbf{không} được dùng làm đầu vào của mô hình dự đoán vì chúng được suy ra trực tiếp từ biến đích (leakage), làm kết quả đánh giá mất tin cậy.
